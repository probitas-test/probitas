# Package Structure

Single-package structure for user-facing Probitas: a library published to npm
(`@probitas-test/probitas`) and JSR (`@probitas/probitas`), and a CLI
distributed as a single binary built with `bun build --compile`.

## Directory Layout

```
probitas/
├── package.json                  # Package manifest (source of truth)
├── deno.json                     # JSR manifest, generated by `bun run jsr:sync`
├── src/
│   ├── mod.ts                    # Main entry point (library API)
│   ├── client.ts                 # Client exports (re-export hub)
│   ├── client/                   # Client re-exports
│   ├── expect.ts                 # Expectation API (re-exports @probitas-test/expect)
│   ├── _vendor/                  # Vendored JSR-only modules (see its README)
│   ├── cli.ts                    # CLI entry point (not published as a library)
│   └── cli/
│       ├── commands/             # CLI commands (init, run, list, check, cache)
│       ├── _worker.ts            # Worker that runs scenarios inside the binary
│       ├── _templates/           # Worker-side run/list logic and IPC framing
│       ├── duckdb.ts             # DuckDB native binding download and cache
│       └── ...                   # Config, reporters, other CLI utilities
├── scripts/
│   ├── compile.ts                # Build the single binary (`bun run compile`)
│   ├── build.ts                  # Build the library for npm (`bun run build`)
│   ├── sync_jsr.ts               # Generate deno.json
│   └── vendor_jsr.ts             # Refresh src/_vendor
├── internal/testing/             # Deno.test-shaped helpers on top of bun:test
├── probitas/                     # Example scenarios (also the end-to-end suite)
└── assets/                       # CLI assets embedded into the binary
```

## Package Responsibilities

### Library API (`src/mod.ts`)

The main entry point provides the user-facing API for writing scenarios:

- Re-exports `scenario` builder from `@probitas-test/builder`
- Re-exports `Skip` class from `@probitas-test/runner`
- Re-exports type definitions (`StepContext`, etc.)
- Exports `client` namespace and `expect` utilities
- Re-exports useful testing utilities (faker, time mocking, spies, etc.)

### CLI (`src/cli.ts`)

Command-line interface for managing and running scenarios. The binary re-spawns
itself as `__worker <run|list>` for each run and talks to the worker over TCP
with length-prefixed CBOR frames. The worker maps every Probitas specifier a
scenario imports (including the Deno-era `jsr:@probitas/*` forms) to the modules
embedded in the binary, so scenarios need no install step.

### Client Integrations (`src/client/`)

Re-exports client packages with unified interface:

- Each client file re-exports from the corresponding `@probitas-test/client-*`
  package
- Provides a single import point for all clients
- Clients with native dependencies must load them lazily (dynamic import), so a
  missing native library never breaks scenarios that do not use it

## External Dependencies

The framework packages live in the
[probitas-packages](https://github.com/probitas-test/probitas-packages)
repository and are versioned independently:

```mermaid
graph TD
    probitas[@probitas-test/probitas] --> builder[@probitas-test/builder]
    probitas --> runner[@probitas-test/runner]
    probitas --> expect[@probitas-test/expect]
    probitas --> clients[@probitas-test/client-*]
    runner --> core[@probitas-test/core]
    core --> discover[@probitas-test/discover]
```

## Testing Strategy

- **Unit tests**: Co-located `*_test.ts` files, run with `bun run test`
- **Example scenarios**: `probitas/*.probitas.ts`, run with
  `bun run probitas run` (from source) or the compiled binary
